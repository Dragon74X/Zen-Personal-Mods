# Antagonistic audit — 18 September 2026

Reviewed the six mods' scripts, styles, preferences, manifests, shared Sine guard and diagnostics against upstream code. Earlier comments and reviews were treated as claims to verify. The review found additional correctness problems beyond Fable's list. Fixes and regression checks are included in PR #70.

This is a source audit of this repository, with targeted checks of its upstream integrations. It is not an audit of every installed third-party mod, every website in Zen Internet, or the user's current browser profile.

## Findings and changes

| Area | Verified problem | Change |
|---|---|---|
| Glassflow, high | A pending snapshot/encoding operation could stop the refresh chain, leaving the first image visible indefinitely. Native backdrop filtering alone was not a demonstrated solution for every transparent content layer. | Repair the fallback chain and add a live native SVG filter for the content beneath the compact sidebar. Sampling can remain completely off. |
| Sine integration, high | Concurrent multi-mod installs share `sine-mods/temp`; stale registry snapshots can overwrite dependency entries. A rejected update can release the outer operation before other producers finish. | Serialize root operations and sibling dependencies, refresh registry data before writes, defer preference reads during replacement, and collect update errors until producers settle. | Tab Unloader, high | Discarding without awaiting the native state flush can read stale form state. Eligibility can change during that flush. | Tab Router, high | Reopening a loaded page in another container could erase history, POST results, drafts or session storage; a native close veto could leave two tabs. | Flush first. Keep the original container when session state is present, loading continues or state cannot be read. Honor the close veto and remove an unused replacement. | Tab Router, medium | Private windows made creator/icon requests despite the README promising otherwise. | Download Prompt, medium | Retiring the hook-owning window dismissed another window's pending question. | Groupflow, medium | Incremental refresh could style a split-view group even though the full refresh excluded it. Enabling favicons did not immediately refresh. | Apply the same split exclusion to dirty refreshes; refresh on the favicon preference change. |

| Preference ownership, medium | Glassflow's Motion override did not restore its prior value. Retired Turbo preferences could overwrite later manual edits or lose failed-restore records. | Restore only still-owned values; preserve failed restoration snapshots and record newly applied values. |

The standalone Sine guard is identical in all six folders. Duplicate packaging lets any one mod install independently; the shared manager marker ensures one guard per browser session. Its replacement requires a restart.

## Glassflow: native blur without page snapshots

Enable **Enable sidebar styling**, **Blur behind the floating panel** and **Native blur through transparent pages**. Disable **Sampled glass**. Keep the separate whole-page and static page-strip blur effects off if only the region beneath the floating sidebar should change. Panel opacity must be below 100% to see through it. The existing `zzglass.sidebar.blur-through-transparent` preference is reused; this replaces its previous clip-path workaround.

The new filter is attached to `#tabbrowser-tabbox`. It blurs `SourceGraphic`, masks that result to the rounded sidebar region, and combines it with the untouched source outside that region. Complementary masks preserve alpha and antialiased edges. The Gaussian output region is limited to the panel plus its blur margin. Firefox supplies updated content pixels; there are no snapshot calls, bitmap copies or PNG encodes in this mode. A generated SVG rectangle supplies geometry only, not an image of the page.

This addresses text/images rendered on transparent pages independently of whether the chrome backdrop filter samples the remote content layer. The panel's native `backdrop-filter` still handles the browser background showing through the page. Geometry tracking runs while the sidebar moves/resizes and stops once settled, with a 1500 ms bound. Disabling, hiding, entering content fullscreen or retiring removes the filter. Both left and right sidebars were checked.

Arc 2.0 adds its own browser transforms, tint and optional clip workaround. Zen Internet injects per-site CSS and keeps its stylesheet late in the page head; My Internet's site rules make different combinations of root, body and inner elements transparent. The new filter operates on rendered content rather than guessing which selector supplies the page background. It does not rewrite the extension's site rules.

Transparent Zen's **Normal** compact-sidebar mode is the relevant configuration. **Mask** hides content beneath the sidebar and **Push** translates content away. Those modes intentionally change what is available behind the panel; filtering cannot restore content that has been masked out.

Remaining rendering limits:

- The geometry mask uses circular rounded corners, not an exact reproduction of every custom `corner-shape` superellipse. Unusual corner styling can differ at the edge.
- The content filter does not capture the desktop behind an OS-transparent browser. OS acrylic and chrome backdrop behavior still depend on the compositor.
- Where native backdrop blur already includes page content, enabling the additional content filter can increase the blur. Adjust its radius or leave the compatibility option off there.
- The filter still costs rendering work and may require an intermediate content surface. Removing screenshot readbacks is not evidence of a measured FPS improvement.
- Windows GPU rendering, OS blur and the user's exact theme settings were not available here. No universal GPU-performance or all-websites claim is made.

The snapshot option remains a fallback. Its timer now survives pending reads, a stalled read can be superseded after 2000 ms, and stale callbacks cannot replace newer frames. The sidebar master setting controls sampling too. Private windows discard hidden frames, and history purge clears retained frames.

## Is Zen Turbo useful?

Its defensible additions are optional speculative connections for unloaded tabs/bookmarks after a dwell, bounded tab-effect suspension during workspace motion, and reversible preference controls. Firefox already implements page-link hover preconnection, so a second wrapper was unnecessary. The native-hover pack now only enables Firefox's HTTPS-page behavior.

The broad network/cache/media/session-store values remain tuning choices, not measured improvements. Larger caches consume memory; speculative connections can be unused; the 30-second session write interval changes persistence timing. Graphics overrides stay off by default. The audit added no aggressive performance pack. Disable a pack before uninstalling if its captured values should be restored.

Turbo's counters record API calls and later origin/container matches. They do not measure successful handshakes, socket reuse or page-load time. Benchmark the desired workload on the actual machine before treating a pack as faster. Keeping only the features with a visible benefit is reasonable.

## Verification

Run from the repository root:

```sh
SINE_MANAGER_SOURCE=/path/to/Sine/src/core/manager.sys.mjs node --test tools/*.test.mjs
python tools/zen-smoke.py --zen /path/to/zen --arc /path/to/Arc-2.0 --transparent /path/to/zen-themes/TransparentZen
```

**67 tests passed, 0 failed, 0 skipped.** The Node suite exercises production functions with browser API fakes, plus four checks executing actual pinned Sine update/install methods with mocked filesystem/network operations. Cases cover failure ordering, delayed producers, nested dependencies, remove/toggle serialization, reinjection, modal ownership, snapshot stalls, form flushing, close vetoes, request cancellation, private lookups, cache invalidation, preference restoration and diagnostic conditions. It does not replace runtime testing of those entire user flows.

The isolated runtime smoke test uses official **Zen 1.22.2b / Firefox 156.0**, all six scripts, Arc CSS and Transparent Zen CSS in a temporary profile. Pillow is a test-only dependency. It checks:

- All six window APIs start.
- Transparent striped content beneath the sidebar blurs; changing black stripes to red updates the filtered pixels with **0 sample ticks and 0 sample frames**.
- The left and right sidebar positions both work; the geometry tracker settles.
- Uncovered pixels remain identical when the filter is disabled.
- Turbo's motion marker preserves the panel and content filters.
- Download Prompt enters native modal state with focus inside and an accessible label.
- Cleanup removes the filter and its SVG definition.

For the Arc fixture, the covered black/transparent stripe crop had channel standard deviation approximately **0.50**, versus more than **40** required for the unblurred crop. Changing stripe color increased the covered red-channel mean by **127.48**. The uncovered region's mean absolute difference after disabling was **0**. These are pixel correctness checks, not performance measurements.

The runtime is Linux headless software rendering. Firefox's CPU snapshot path does not implement the backdrop-filter paint operation, so screenshot results cannot validate compositor-only CSS backdrop blur. The test deliberately checks the SVG content filter and separately inspects the panel's computed backdrop style. The container required sandbox-disabling environment flags to launch this isolated test; these are not written to mod code or recommended for an ordinary browser profile.

## Remaining integration limits

Sine's direct UI writer for the **no-updates** flag bypasses the guarded manager methods. The guard does not make every upstream registry write transactional, repair missing installations, or roll back every archive failure. Avoid changing that flag during an install. Obtain a working guard copy, restart, and reinstall already-damaged mods one at a time; see [recovery](../README.md#sine-update-recovery). Revisit/remove the guard when upstream provides transaction-local staging.

SessionStore protection covers state Firefox serializes. It cannot prove that an arbitrary application's in-memory draft is saved. Tab Unloader keeps tabs when form-state inspection fails; Tab Router leaves their container unchanged. Website-specific unsaved work can still require exclusions.

The smoke test does not perform a real network download/replace, navigate every workspace/container combination, or reproduce the user's Windows profile. The source and mocked tests substantiate those fixes within the stated API contracts, with those runtime limits retained.
