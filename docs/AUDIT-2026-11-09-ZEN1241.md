# Zen 1.24.1b compatibility and cohesion pass

Reviewed on 9 November 2026 against Zen **1.24.1b** (tag commit `12c01ff1`,
Firefox 159.0.1, released 6 November), 35 commits after 1.24b. The Zen `dev`
branch had moved to Firefox 160.0 (`7619449a`) the same day. Upstream Sine has
no commits after the pinned `fb0bd4c`, so the update guard's wrapped internals
are unchanged.

Before this pass `main` was preserved as
`backup/main-pre-zen-1.24.1b-2026-11-09` (`3c15991`).

## Fixed in this pass

### Iconflow and Glassflow: Favorites and the close X

**Favorites moving on hover.** A Favorite's icon slides 12px aside on hover in
Zen 1.24.1b whenever something shows the Favorite's minus (reset) button. Zen
1.24.1b added `position: relative` to `.tab-content > :is(.tab-close-button,
.tab-reset-button)` in its own author sheet, which outranks a theme's ordinary
`position: absolute` on that button, so the minus takes a flex slot. Arc 2.0's
optional Essentials unload button reproduces it exactly (icon x 33 to 21). It
happens with Iconflow 1.21.12 and 1.21.13 alike and not on Zen 1.24b, so the
trigger is the Zen update, not Iconflow's 1.21.13 paint change. Iconflow
1.21.14 keeps that minus out of the Favorite's layout and repaints the Morph
minus that the theme's background shorthand blanked. Stock Zen keeps the minus
hidden on Favorites, so the rule is inert without such a theme.

With the suite at defaults and Arc 2.0 at its defaults, nothing moved in 105
Favorite rows (four icon sets; loaded, unloaded, selected and playing Favorites;
sidebar expanded, collapsed and both compact states; `:hover` locks and
WebDriver pointer moves). The only change was Glassflow's in-place grow (at most
0.21px of centroid drift; 0.67px at DPR 1.5 from pixel alignment). The user's
report was made without Arc's unload button, so another installed theme or mod
showing the Favorite's minus or close box remains the most likely cause there.
[`tools/favorite-hover-probe.js`](../tools/favorite-hover-probe.js) reports any
Favorite icon shift and the stylesheet rule responsible.

**Close X grow-in.** Glassflow's close-button motion scaled `.tab-close-button
image`, which matched nothing on either 1.24b (the close is itself an image) or
1.24.1b (a box drawing two lines), so the 65%-to-100% grow-in never ran.
Placement was already right: the X sits on the favicon's resting slot and fades
in. Glassflow 3.74.23 grows Zen 1.24.1's two lines instead, keeping Zen's own
rotate/width easing and reduced motion; the 24px target does not move or
resize. Iconflow artwork, which replaces those lines, is unchanged.

**Library button size.** Zen 1.24.1b draws the Library sprite at 20px instead of
18px scaled 8%. Iconflow's fixed 1.125 factor then left it undersized at larger
Icon sizes (22.5px against 25px for Zen's proportion at 20px icons). Iconflow
now scales Zen's own size with the icons; Circuit stack and **Same size as the
other buttons** are unchanged.

Checks: `tools/zen1241-iconflow-hover.py` (81 native checks on 1.24.1b, 80 on
1.24b; the old source fails the Favorite and close-line checks),
`tools/zen1241-iconflow-library.py` (96 on both) and
`tools/zen1241-iconflow.test.mjs`.

### Groupflow: saved gradients on group headers

Zen 1.24.1b's `getGradient()` returns window-sized background layers whose base
stops use `--zen-gradient-base-*` variables that only Zen's own backgrounds
define, so a group header dropped the value and showed one colour fading out.
`tools/zen-routing-smoke.py` fails its saved-gradient tint check on 1.24.1b
with the old code. Groupflow 1.75.7 lays the base stops across the header and
keeps the middle strip of a third colour's overlay; values from Zen 1.24b pass
through unchanged.

Zen 1.24.1b also lets a pinned tab inside a folder become an Essential
(gh-16418). Adding pinned and unpinned tabs from nested folders to Essentials,
restarting, removing them and restarting again left folder ids, nesting,
counts, badges and startup folding intact, and a second window mirrored the
change. Groupflow reads none of the removed gradient fields, and Zen's new
nested space-id stamping matches what Groupflow already writes.

Checks: `tools/zen1241-groupflow-smoke.py` (three launches, two windows) and
`tools/zen1241-groupflow.test.mjs`.

### Glassflow Library: space cards

Zen 1.23b painted a Library space card's gradient on `.zen-library-space::before`
with `--zen-library-space-gradient`. Since 1.24b that variable is gone and the
card paints through a child, `.zen-library-space-background`, which carries the
gradient, the grain and the shadow. Glassflow Library still styled the old
pseudo-element, so on 1.24b and 1.24.1b **Space gradient strength**, **Card
shadow** and **Glass sheen** changed nothing (measured: identical interior
pixels across those settings), the radius missed the visible layer, and with
sheen on the card's background declaration was invalid. In 1.24.1b compact
mode Zen also gives that child its new 80% readability tint and a 42px blur.

The card glass now targets the child: gradient strength fades gradient and
grain together, the fill alone sets the card's translucency (Zen's compact
base, tint and blur are left off cards that sit on the window background),
`::before` carries Zen's shadow and the sheen, and the rim replaces Zen's thin
compact outline. Defaults and labels are unchanged; the reduced-transparency
and contrast fallback still paints Canvas. With the blur restored by a test
sheet, a card changed by at most 7–8 of 255 levels, against 65 for a control
blur over text, so leaving it off costs no visible detail.

Checks: `tools/zen1241-glassflow-library-cards.py` (49 native assertions; main's
stylesheet fails the first) on Zen 1.24.1b and 1.24b, and
`tools/zen1241-glassflow-library.test.mjs`.

## Firefox 160 (next Zen release)

**Checked 14 November 2026 on Zen 1.24.2b (Firefox 160.0, Linux, Xvfb):** the
Node suite with upstream Sine and the native runtime tests passed (329 passed,
0 failed, 9 skipped), and so did the twelve native runners: `zen-smoke` (default,
`--native-integration`, `--actions`), `zen-routing-smoke`, `zen-settings-smoke`,
`zen-state-motion-smoke`, `zen-mediaflow-controls-smoke`, `zen-freeze-smoke` and
the four `zen1241-*` checks. Sine's script loading, Mediaflow's window actors,
Tab Unloader's discard path and the `-moz-pref()` queries all ran. The settings
runner's `uncaught exception: undefined` lines come from Firefox's own
preferences widgets (`lit-utils.mjs`), appear identically on 1.24.1b, and no mod
code is involved. The notes below were written before that release.

The current twilight download could not be confirmed as a Firefox 160 build
from this environment, so no native run was made against it. APIs these mods
depend on that a Gecko major update could plausibly affect, most likely first:
Sine's script loading and `windowUtils.loadSheet`; Mediaflow's
`JSWindowActor` registration; Tab Unloader's `prepareDiscardBrowser()`;
`-moz-pref()` media queries. Run the native suite against the first 160-based
release before relying on these.

## Not verified here

Linux Xvfb runs cannot show Windows compositor output or physical pointer
input. Synthetic `:hover` locks and WebDriver pointer moves are recorded as
such.
