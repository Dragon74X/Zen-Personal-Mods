# Zen 1.23.3b compatibility and clean icons

Baseline: `a8105d7131e307f8ea5471bd7585e6148f20d5b6` (Iconflow 1.18.4).
Rollback branch: `rollback/pre-zen-1233-clean-icons-20261017`.

## Releases

- Iconflow 1.19.0: **Icon set → Circuit: clean** adds 59 matching icons and the alternate reload. Same geometry, sizing, spring timing, states and actions; restrained Library-style fills, no sheen, halo or hover glow. The original remains selectable and existing per-button choices remain authoritative. Clean SVGs total 4.1 MB; assets load only when selected. No extra animation loop.
- Iconflow rendering repair: static SVGs resolve through Sine's `chrome://` mapping. Generated native strips use temporary files exposed through `resource://`, allowing Gecko's default contextual SVG paint without changing the content security preference. Retirement removes those files and mappings. The strip's outer aspect ratio no longer clips non-square icon boxes. Circuit clears competing theme masks; native mask artwork retains whole-icon motion.
- Glassflow Library 1.2.6: extra rows follow the native session download list and delegate speed labels and retry to Zen's helpers. Cancel and Show in Folder match the native widget; blocked downloads retain native confirmation.
- Glassflow 3.69.2: when Glassflow owns the compact sidebar, its native blur-off/reduced-transparency choice also overrides Arc's legacy acrylic rule.

## Upstream check

[Zen 1.23.3b](https://github.com/zen-browser/desktop/releases/tag/1.23.3b) uses Firefox 158.0. Its Library API changes require the row updates above. Routing continues through the native matcher. Folder creation fixes and the compact-layout event change require no production change here. This release adds no new blur API requiring a replacement of Glassflow's existing native integration.

The broken icon paint came from file/data SVGs losing contextual theme colors. Firefox's [SVGContextPaint implementation](https://github.com/mozilla-firefox/firefox/blob/main/layout/svg/SVGContextPaint.cpp) permits those colors on trusted chrome/resource image URLs. No global SVG preference is weakened.

## Download popup handoff: Glassflow Library 1.2.7

Zen's compact-mode enter handler returns early while the sidebar still has its hover attribute. Briefly crossing outside the sidebar on the way from recent downloads starts its hide timer; returning before that timer expires does not cancel it. The sidebar then closes under the pointer. This was reproduced with actual pointer movement in Zen 1.23.3b.

The existing Library `mouseenter` listener now cancels Zen's pending sidebar hide when the pointer re-enters the sidebar. It also cancels a queued hide frame for zero-delay hiding. No new listener, timer, polling, visual change or preference migration is added. Existing retirement removes the listener. Remaining over the page still allows normal auto-hide.

Run `python tools/zen-smoke.py --zen /path/to/zen --library-hover`, optionally with `--arc /path/to/Arc-2.0`. It uses disposable profiles and actual pointer events, without pinning the sidebar open. Cases cover left/right, expanded/icon-only, hover/click opening, direct return, return before/after the popup closes, and staying over the page.

Verification: all 32 cases passed in plain Zen and all 32 with Arc; all 159 Node tests passed. The original failure was reproduced before the change and the same pointer path stayed open afterward.

The same rollback checkpoint above contains Glassflow Library 1.2.6. Restore that directory with a fresh version and `updatedAt` to publish a revert without undoing Groupflow.

## Cleaner icons and saved downloads: Iconflow 1.19.1 / Glassflow Library 1.2.8

Circuit Clean's narrow arrow shapes and bars were still outlined on both sides. They now use solid shapes. Compact mode uses one window frame and one moving divider; sidebar ticks and picture-in-picture/fullscreen inset borders are removed. Small markers use solid fills. The Library artwork, glass/neon set, animation timing and button functions are unchanged. All 60 Clean icons were inspected at toolbar size and at three animation positions in Zen; 31 SVGs changed, totaling 2.2% fewer bytes.

Zen 1.23.3b changed its download widget from history-inclusive data to current-session data. With no session downloads, its native popup opener refuses to open. Library now fills available slots from Firefox's limited history view (42 history entries maximum), keeping Zen's native session rows. First click opens the configured 1–8 recent downloads; second click opens the full Library. When no saved or session downloads exist, the first click still opens the Library. Private windows remain private-session-only. Added rows retain their existing open/retry/cancel/show-in-folder actions; context menus and dragging remain available on Zen's native rows.

History-only opening reuses Zen's stack attributes and existing close animation. Hidden native placeholders no longer consume the visible count. The first click waits for the initial history batch, and retired script instances cannot subscribe after asynchronous initialization. No new polling, dependency or preference is introduced.

Validation: 159 Node tests passed, including bounded rendering with 1,000 downloads and 25 native-row/count combinations. Native pointer checks passed in plain Zen (14 history checks + 32 sidebar handoffs) and with Arc (15 history checks + 32 handoffs, including public-history isolation in a private window). These cover history-only, mixed session/history, 1/3/4/8 visible entries, first/second click and clearing history. The full Zen runtime suite also passed 72 contextual icon paint cases and 21 download pop-out icon selections. GPU performance on the user's machine remains unmeasured.
