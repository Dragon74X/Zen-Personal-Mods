# Native settings presentation

Baseline: `7a1d2c85575ea10a6a1b626c46eab7e2da56ddfe`.

The 10 menus previously contained 524 controls: 180 booleans, 174 dropdowns,
170 text fields, plus 74 separators. They now contain 527 controls: the same
524 functional settings plus three navigation dropdowns. An order-independent
contract digest verifies every original key, type, default, and option value.

## Changes

- One shared wrapper, packaged identically with all 10 independently installable
  mods. Exact mod IDs and preference namespaces gate presentation changes.
- Native `moz-toggle` switches replace checkbox rows and their original anonymous
  click handlers. The switch's pressed value is the only Boolean writer. Labels,
  defaults, and On/Off text remain visible. Descriptions appear on hover or keyboard
  focus, with an info badge beside the label. The native graphic stays
  32×16 CSS px; its effective pointer target is at least 44×44 CSS px.
- Native HTML selects preserve typed option values. Firefox's XUL combobox reads
  descriptions from the selected popup option, so its closed state did not expose
  inline help through `aria-describedby` in the tested browser. Using a native
  select resolves that without building a custom menu. Empty and unknown saved
  values remain visible as a disabled current-value option until changed.
- Native primary-button color pairs fix the tested Zen switch contrast failures
  in dark mode. Forced colors use system button colors. Focus and keyboard
  behavior remain native.
- Per-document preference subscriptions share one observer per watched key.
  Removed rows release subscriptions and added handlers; unloading releases the
  document registry. Configure visibility follows the card's header switch.
- Default annotations come from schemas. Fractional opacity values display and
  edit as percentages; CSS percentage strings retain that format. Router banner
  opacity retains numeric 0–100 storage. Library scale uses × and Mediaflow hover
  delay uses ms while preserving their stored values.
- Applicability fixes cover custom/fallback color, shared secondary color, four
  end-tint modes, Groupflow curves and connector options, Router picture exclusions
  and path naming, Peekflow placement/pictures, and empty Router/Unloader sections.
  Duplicate tooltip and CSS hiding rules were removed after schema checks.
- Hover descriptions now use one native popover per settings document, positioned
  within the viewport above the scrolling dialog. Its text can be selected; Escape
  dismisses it without closing settings. The original descriptions remain linked
  to controls and available in Firefox's accessibility tree while visually hidden.
  Closing, scrolling, rebuilding, or unloading retires the visible tooltip.
- Glassflow tab states, Groupflow folder states, and Iconflow button categories
  use the existing navigation mechanism. Everything and legacy empty pages remain
  supported. Hidden values are retained.
- Router rules use a native multiline field and the shipped `TabRouter.validateRules`
  validator. Invalid edits retain stored rules.

## Verification

```sh
SINE_MANAGER_SOURCE=../Sine/src/core/manager.sys.mjs node --test tools/*.test.mjs
MOZ_DISABLE_CONTENT_SANDBOX=1 python tools/zen-settings-smoke.py \
  --zen ../zen/zen --sine ../Sine/src --output ../settings-evidence
```

The native check uses disposable profiles, actual Zen 1.23.4b / Firefox 158.0.1,
Sine `fb0bd4ca6af888f10648e126947f7d1f82228433`, Sine's original parser/loader,
and Firefox controls. It stubs Sine's unrelated script-rebuild operation and
loads the shipped Router validator. No existing user profile is attached.

Native: **96 assertions passed** across an initial launch and restart.
Node: **216 passed, 0 failed, 0 skipped**, including upstream update serialization
and recovery checks. Native results and screenshots are generated by the command
above. The native assertions cover:

- All 10 dialogs, 180 switches, and name/help associations on all 527 controls;
  Firefox's actual accessibility tree for 71 visible controls across the menus.
- Trusted pointer, label, Space and Enter activation: one Boolean write each.
  Disabled activation: zero writes. Description clicks: zero writes. Tab focus,
  native toggle-button semantics, accessible pressed state, and the 44px hit area.
- External preference changes, reset, reopen, rebuild, enable/disable, and two
  settings windows. Rebuilt and closed dialogs become collectible after native memory-pressure cleanup and forced GC; retired
  controls stop synchronizing. A second rebuild causes zero presentation-only
  preference writes.
- Both Configure visibility cases; affected condition combinations; saved empty
  and unknown dropdown values; percentage editing; typed dropdown writes; valid
  and invalid multiline rules; restart retention of state, opacity, navigation,
  and hidden values.
- Light, dark, forced colors, reduced motion, 200% zoom, and a measured 320 CSS-px
  content viewport. Dialog/row overflow checks and inspected native screenshots.
- Descriptions hidden at rest; pointer hover on switches, dropdowns and text fields;
  selectable tooltip text without toggling; keyboard focus; Escape dismissal;
  accessible descriptions after dismissal; close cleanup; tooltip bounds in all
  six layout modes; working description tooltips after restart.

## Already resolved findings and limits

Custom-source **OR** custom-fallback was already correct in the schema; its
conflicting CSS gate caused the missing field. Library card fill already stored
`70%`; Router banner opacity already stored numeric `25`. Those contracts remain
unchanged. Path depth, ignore words and aliases also serve matching Nexus rules,
so gating all of them behind unmatched sorting was rejected. No dependency was
added between Glass rim and Outer glow. Previously released picture recovery,
soft icon corners, banners, close-glyph animation and warmup changes are retained.

The native verification is Linux/headless. It does not establish screen-reader
speech on Windows/macOS, arbitrary third-party theme contrast, every possible
preference combination, or performance. Collection checks cover the tested
rebuild/close paths; they are not a whole-browser memory audit.

One browser restart is required after Sine installs the updated shared background
module. Merely reopening a settings dialog does not replace a cached module.
